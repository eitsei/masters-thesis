# FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance
**Authors:** Lingjiao Chen, Matei Zaharia, James Zou | **Year:** 2023
**Category:** Routing

### 📝 Abstract & Relevance Summary
This paper addresses the significant financial and computational costs associated with querying popular LLM APIs, such as GPT-4, which hampers their adoption in high-throughput enterprise scenarios. The authors present a framework consisting of three core strategies for cost reduction: prompt adaptation (prompt selection, query concatenation), LLM approximation (completion cache, model fine-tuning), and LLM cascade. A concrete implementation of LLM cascade, called FrugalGPT, is proposed. FrugalGPT adaptively routes queries through a sequence of increasingly powerful models based on a reliability score generated by a lightweight classifier. This method is highly relevant to both **Operational Efficiency** (by reducing API fees by up to two orders of magnitude) and **Output Quality** (by utilizing the diversity of multiple models to occasionally output correct answers where the best individual model fails).

### 🚀 Efficiency & Cost Metrics (RQ1 & RQ2)
- **Latency Impact:** Average latency is reduced when queries are resolved early by smaller models in the cascade (e.g., GPT-J). The routing overhead is negligible as it uses a lightweight classifier (like DistilBERT) to score reliability. However, sequential cascading could theoretically increase latency for hard queries that require traversing all models to the end. Model fine-tuning (LLM approximation) improves latency as a byproduct by eliminating the need for long, few-shot prompt instructions.
- **Cost & Token Usage:** FrugalGPT achieves up to **98.3% cost reduction** compared to using GPT-4 alone while matching its accuracy. Specific cost savings to reach the same accuracy as the best individual model are:
  - **HEADLINES:** 98.3% savings ($33.1 down to $0.6)
  - **OVERRULING:** 73.3% savings ($9.7 down to $2.6)
  - **COQA:** 59.2% savings ($72.5 down to $29.6)
- **Throughput:** Not explicitly evaluated in Tokens Per Second (TPS), but routing queries to smaller, locally-hosted or cheaper APIs naturally reduces load on expensive APIs and enables higher concurrent request throughput.

### 🏆 Quality & Accuracy Metrics (RQ3)
- **Quality Metrics:** Accuracy (exact match or task-specific metrics) evaluated against ground truth labels.
- **Benchmark Data:**
  - **HEADLINES:** Financial news commodity price trend classification (Size: 10,000 queries, domain: Finance).
  - **OVERRULING:** Legal document overruling sentence classification (Size: 2,400 queries, domain: Law).
  - **COQA:** Passage reading comprehension adapted to direct query answering (Size: 7,982 queries, domain: general/conversational).
- **Judge Setup:** Evaluated against ground-truth datasets; no LLM-as-a-judge was required. The reliability scoring function uses a DistilBERT regression model trained to predict correct/incorrect predictions of cheaper LLMs.

### ⚖️ The Trade-off Analysis
- **Efficiency-Quality Equilibrium:** FrugalGPT demonstrates that matching or even exceeding the accuracy of the best model (GPT-4) is possible while significantly lowering costs. For example, on the HEADLINES dataset, FrugalGPT improves accuracy by 1.5% over GPT-4 while reducing cost by 80%.
- **Pareto Frontier & Combinations:** Outlines a multi-strategy space. Combining prompt adaptation, completion cache, model fine-tuning, and sequential LLM cascading defines a cost-accuracy Pareto frontier, allowing developers to set a budget constraint and maximize accuracy.
- **Chunking/Routing Strategy:** Uses a sequential model cascade with a length of 3 models.
  - *Example (HEADLINES at $6.5 budget):* Routes to GPT-J first. If the reliability score is $>0.96$, it stops and returns the answer. Else, it routes to J1-Large. If the J1-Large reliability score is $>0.37$, it stops. Otherwise, it invokes GPT-4.
- **Enterprise Suitability:** Highly suitable for production workloads due to deterministic threshold routing. However, it requires labeled training data to learn the threshold parameters and classifier, and is susceptible to performance drops if the query distribution shifts significantly.

### 📊 Methodology & Bias Note
- **Evaluation Framework:** Evaluated using custom training and test splits of HEADLINES, OVERRULING, and COQA datasets.
- **Bias Detection:** Highlights that more expensive models do not always outperform cheaper ones (e.g., J1 is more expensive than GPT-3 on HEADLINES but has inferior performance), and cheaper models are often complementary to expensive ones, occasionally resolving queries correctly where GPT-4 fails (maximum performance improvement of up to 6%).

### 🔍 Technical Implementation
- **Portability:** The cascading, scoring, and conditional logic are language-agnostic and fully compatible with a Java/Spring AI stack. The reliability classifier (e.g., DistilBERT) can be deployed as an independent sidecar microservice.
- **Key References:**
  - Chen, L., Zaharia, M., Zou, J. (2020). *FrugalML: How to use ML prediction APIs more accurately and cheaply.* NeurIPS 2020.
  - Arora, S., et al. (2022). *Ask me anything: A simple strategy for prompting language models.* arXiv preprint arXiv:2210.02441.

### 💡 Key Takeaway for Thesis
- FrugalGPT proves that sequential query routing using lightweight classifiers can slash LLM operational costs by up to 98% while maintaining or even improving output quality by exploiting model diversity.
